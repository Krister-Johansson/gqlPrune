---
title: Usage patterns
description: Which identifiers count as a use of a GraphQL operation or fragment, the default patterns, the placeholders, and how to set custom patterns with usagePatterns and fragmentUsagePatterns.
---

A usage pattern is a template for an identifier that counts as a use of a definition. gqlPrune expands each pattern for every operation and fragment, then looks for a reference in your source that resolves to one of the expanded identifiers (see [how detection works](/concepts/how-detection-works)). If your client or code generator names things differently from the defaults, set your own patterns, or operations you use will be reported as unused.

## Default operation patterns

The defaults match the names GraphQL Code Generator emits with the `typescript-react-apollo` plugin. For an operation `query GetUser`, they expand to:

| Pattern | Expands to |
| --- | --- |
| `use{Name}{Type}` | `useGetUserQuery` |
| `use{Name}Lazy{Type}` | `useGetUserLazyQuery` |
| `use{Name}Suspense{Type}` | `useGetUserSuspenseQuery` |
| `{Name}Document` | `GetUserDocument` |

The operation counts as used when a reference resolves to any one of them.

## Default fragment patterns

A fragment counts as used when an operation spreads it, directly or through other fragments. It also counts as used when a reference in source resolves to one of its fragment patterns. The default is one pattern, which matches the constant codegen emits for fragment masking:

| Pattern | Expands to, for `fragment UserFields` |
| --- | --- |
| `{Name}FragmentDoc` | `UserFieldsFragmentDoc` |

## Placeholders

Operation patterns take four placeholders. Fragment patterns take only `{name}` and `{Name}`, because a fragment has no operation type.

| Placeholder | Replaced with | For `query getUser` |
| --- | --- | --- |
| `{name}` | the name as written | `getUser` |
| `{Name}` | the name with its first letter in upper case | `GetUser` |
| `{type}` | the operation type: `query`, `mutation` or `subscription` | `query` |
| `{Type}` | the operation type with its first letter in upper case | `Query` |

`{Name}` only changes the first letter. An operation named `getUser` gives `GetUser`, and one named `GETUSER` stays `GETUSER`.

## Each pattern must expand to an identifier

Since 4.0, every pattern has to expand to a valid JavaScript identifier. gqlPrune decides usage by references to identifiers, so a pattern containing a dot, a slash or a space could never match anything. Patterns such as `use{Name}{Type}` and `{Name}Document` pass. A pattern such as `{Name}.graphql` stops the run with exit code 2 before anything is scanned.

This command passes a pattern that is not an identifier and fails with exit code 2:

```bash
npx gqlprune --graphql ./graphql --src ./src --pattern '{Name}.graphql'
```

The run prints:

```text
Every entry in "usagePatterns" must expand to an identifier: "{Name}.graphql" expands to "Sample.graphql" for an operation named Sample. Usage is decided by references to identifiers, so a pattern with other characters can never match.
```

Every entry also has to be a non-empty string. A YAML list of numbers, such as `usagePatterns: [8080]`, stops the run with exit code 2 as well. The same checks apply to `fragmentUsagePatterns`.

## Custom patterns

### usagePatterns

Set `usagePatterns` in `gqlPrune.config.yaml` to replace the default operation patterns. Your list replaces the defaults; it does not add to them. Repeat any default you still want.

This config matches urql-style hooks and the generated document constant:

```yaml
graphqlDir: ./graphql
srcDir: ./src
usagePatterns:
  - use{Name}{Type}
  - '{Name}Document'
```

Quote a pattern that starts with `{`, since YAML would otherwise read it as a mapping.

This config matches the services generated by the `typescript-apollo-angular` plugin, such as `GetUserGQL`:

```yaml
graphqlDir: ./graphql
srcDir: ./src
usagePatterns:
  - '{Name}GQL'
  - '{Name}Document'
```

This config adds the infinite and suspense hooks the `typescript-react-query` plugin generates:

```yaml
graphqlDir: ./graphql
srcDir: ./src
usagePatterns:
  - use{Name}{Type}
  - useInfinite{Name}{Type}
  - useSuspense{Name}{Type}
  - useSuspenseInfinite{Name}{Type}
  - '{Name}Document'
```

### fragmentUsagePatterns

Set `fragmentUsagePatterns` to replace the default fragment pattern. An explicit empty list turns off source detection for fragments, so only spreads from operations keep a fragment alive.

This config counts only fragment spreads:

```yaml
graphqlDir: ./graphql
srcDir: ./src
fragmentUsagePatterns: []
```

### --pattern and --fragment-pattern

The flags `--pattern` and `--fragment-pattern` set the same lists from the command line. Both are repeatable. A flag replaces the list from the config file rather than adding to it.

This command scans with two operation patterns and the default fragment pattern written out:

```bash
npx gqlprune --graphql ./graphql --src ./src --pattern 'use{Name}{Type}' --pattern '{Name}Document' --fragment-pattern '{Name}FragmentDoc'
```

Quote each pattern so the shell passes the braces through.

## Patterns from a codegen config

When gqlPrune reads your GraphQL Code Generator config, it derives `usagePatterns` and `fragmentUsagePatterns` from the plugins it recognizes, and the derived patterns replace the defaults. A pattern you set in `gqlPrune.config.yaml` or with a flag takes precedence over a derived one. See [codegen](/configuration/codegen) for the plugin table.

## Patterns to avoid

A bare `{Name}` pattern matches any identifier that happens to share the operation's name, so it reports too much as used. Every extra pattern is another way for a dead operation to look used, so keep the list to the names your code actually calls.

This command prints, for each unused operation, the identifiers its patterns expanded to:

```bash
npx gqlprune --verbose
```
